# 商品分类与主食份数测算需求文档

## 目标

商品维护需要支持门店级商品分类，并在所有组合测算中使用“主食份数范围”约束真实点餐场景。该规则用于让单人餐、双人餐、多人餐的成本测算、活动设计、最终组合结果和定价评估保持一致。

## 商品分类

商品分类是门店商品属性，不属于平台属性。不同门店可以对同名商品维护不同分类。

支持分类：

- 主食：饭团等直接贡献主食份数的商品。
- 小吃饮料：饮品、小吃、茶叶蛋等可搭配商品。
- 加料：小料、配菜、蘸料、加购项等。
- 套餐：由其他商品组成的组合商品，可以贡献 1 份、2 份或更多主食份数。
- 其他：无法自动判断或暂未分类商品。

## 主食份数

每个商品维护 `主食份数`：

- 主食默认 1。
- 小吃饮料、加料、其他默认 0。
- 套餐默认根据商品名识别：单人/一份为 1，双人/两份为 2，多人/三人/三份为 3；无法识别时默认 1。
- 页面允许手动修改，手动值优先于自动识别。

## 门店测算主食范围

每个门店维护统一的测算主食份数范围：

- 主食份数最低：默认 0。
- 主食份数最高：空值表示不限。
- 所有组合的主食份数合计必须落在该范围内。
- 若设置单人餐为 `1-1`，则 `单人套餐(1份)` 或 `1个饭团 + 小吃/饮料` 有效，`单人套餐 + 饭团` 无效。
- 若设置双人餐为 `2-2`，则 `双人套餐(2份)` 或 `2个饭团 + 小吃/饮料` 有效。
- 如果套餐再搭配其他主食，按主食份数合计判断，超过当前范围则视为多人餐场景，不进入当前测算。

## 适用范围

主食份数范围统一作用于：

- 最终商品组合结果。
- 测算最优活动。
- 成本测算。
- 活动设计。
- 定价评估。

成本测算、活动设计和最终组合结果通过统一组合枚举器过滤。定价评估不做全量组合枚举，但压力场景必须按同一主食份数范围构造，避免定价建议脱离当前单人/双人/多人边界。

## 场景 Tab

组合结果页和活动设计页提供场景 Tab：

- 单人：主食份数范围 `1-1`。
- 双人：主食份数范围 `2-2`。
- 多人：主食份数范围 `3-不限`。

场景 Tab 是页面级临时测算条件，不写回门店维护中的默认主食范围。每个 Tab 独立缓存结果，切换 Tab 只切换展示，不覆盖其他场景已经生成的组合结果、最优活动建议或活动设计结果。

## 导入与兼容

- 美团/饿了么商品表没有分类字段时，按商品名自动识别分类和主食份数。
- 商品 CSV 可选导入 `商品分类`、`主食份数` 字段。
- 旧浏览器数据库不删除，加载时自动补齐分类、主食份数和门店主食范围。

## 非目标

1. 不自动拆解套餐包含哪些具体商品。
2. 不为不同平台维护不同商品分类。
3. 不用商品分类替代上下架、起送价、单点不送规则。
