# 后台核对与同步

入口：`/backend-sync`，菜单“后台核对与同步”。三个平台费用页也提供入口。

## 使用

1. 选择工具中的门店和对应平台。填写后台显示的门店名称、采集时间、来源菜单路径及有效期。
2. 导入 Excel、CSV 或粘贴带表头的表格。可下载含费用、商品、活动三张表的空白模板。文件在当前浏览器解析，不直接连接商家后台，也不要求登录凭证。
3. 点击“排查差异”，查看当前值、后台值和无法同步的原因。只勾选准备更新的项目，核对后确认同步。
4. 重新运行测算。同步记录保存旧值和来源；工具现值与记录不一致时显示“同步后有变更，需复核”。

## 数据范围

- 费用：平台费用页已有的佣金率、保底佣金、距离／金额配送阶梯、商家减配成本、当前时段附加费。
- 商品：根据工具商品 ID、商家商品编码或唯一名称匹配，更新所选平台售价、包装费和上架状态。保留商品成本、类别、套餐组成及其他平台数据。未匹配商品不自动创建，因为成本等经营数据尚未取得。
- 活动组：满减、商家承担的订单券、红包加码、商品折扣、商家承担的基础红包阶梯、京东补贴券分摊。每组替换前后均展示；必须导出完整的本店本平台活动组。未提供的项目保留，空白不视为 0。
- 不同店、不同平台的基础红包独立保存，并实际参与组合测算、活动设计及定价评估。基础红包金额为商家承担，不是未经分摊的用户红包面额。

常见商品表表头：`商品名称、商家商品编码、售价、包装费、上架状态`。
费用表表头：`类别、项目、后台值`；类别填“费用”，项目使用模板名称。
活动表类别：`满减、订单券、红包加码、商品折扣、基础红包、京东补贴券`；状态需明确启用或停用。
京东补贴券的商家承担与平台承担之和应等于券面金额，加码单列。

最低价测算中，“商家加码”填写最大可同时生效的追加金额；例如全天3元与新客/Plus各1元且两类身份互斥时，填写4元而非5元。网站无需模拟人群与时段，人工核定最大可行金额及同享范围即可。京东维护页的“补齐参考券（停用）”只追加缺少的参考项，保留现有金额与加码；核实本店报名和最大加码后再启用保存。

## 不支持的规则

模板不是平台万能解析器。无法识别的表头和项目明确报错，不猜测未知含义。特殊互斥规则、不同佣金基数、起送价口径等若与现有模型不同，应填写特殊规则区；整份摘录会标记不可同步，先调整模型再重新核对。工具当前使用的费用与优惠模型并未因此自动升级为平台官方完整规则。

门店不一致、未来采集时间、已过有效期、重复项目、商品匹配不唯一、负数、缺失状态、错误分摊等均阻止对应更新。来源中包含登录凭证参数会拒绝导入。用户确认只更新本地测算配置，不操作平台后台。

## 保存与撤回

复用现有浏览器／后台数据保存方式。先完成保存再更新页面状态，保存失败不显示同步成功。同步前重新检查预览值；预览后配置发生变化会要求重新核对。
撤回只恢复本次修改项目，不覆盖其他数据；项目同步后有后续修改时阻止撤回。记录保留，撤回会加标记。修改商品或费用后，活动扫描签名会变化，需要重新扫描；旧测算结果不自动视为新规则下的结果。

验证：`node scripts/check-backend-sync.cjs`（包含费用回归检查）、TypeScript 类型检查及网页交互核对。
