# 成本测算技术方案

## 设计原则

- 成本测算使用独立算法，不复用包含门店满减、门店订单券、门店加码、商品折扣的最终组合测算算法。
- 成本测算利润率目标来自平台通用定价策略阶梯，不再使用页面固定目标利润率。
- 组合枚举统一通过 `enumerateStoreCombos`，该函数负责最大件数、单 SKU 件数、测算总价范围、主食份数范围和最大检查数保护。
- 成本测算的业务计算拆分为三个步骤：组合合法性、整单计算、商品分摊。
- 所有金额统一使用 `roundMoney` 做两位小数归一。

## 核心流程

1. 根据当前门店和平台筛选生成待测平台列表。
2. 使用 `enumerateStoreCombos` 枚举数量组合。
3. 对每个平台调用 `evaluateCostSpaceCombo`。
4. `evaluateCostSpaceCombo` 内部按平台上下架、门店总价范围、成本测算页原价小计范围、起送价、满减/券预留空间、平台基础神券/爆红包、加码预留空间、支付价区间判断是否生成有效订单行。
5. 对每条订单行调用商品分摊逻辑生成商品组合明细。
6. 按 `platform + productId` 聚合商品诊断。
7. 输出商品诊断表、商品组合明细和神券/爆红包阶梯命中分析。
8. 对低于目标利润率的商品，根据缺口最大的组合估算建议平台售价，并允许用户确认后写入平台价和调价记录。

## 关键函数

### enumerateStoreCombos

职责：

- 枚举门店商品数量组合。
- 按当前平台判断上下架，下架商品数量上限为 0，不进入该平台组合。
- 保证组合至少包含一个可单点商品。
- 使用测算总价范围做递归剪枝。
- 使用主食份数范围做递归剪枝和组合合法性过滤。
- 使用 `maxChecks` 防止组合爆炸。

### buildCostAnalysisTotals

职责：

- 按 `平台价 + 当前平台打包费` 计算原价小计，按成本价计算成本。
- 不应用门店商品折扣。
- 下架商品导致当前平台组合无效。

### evaluateCostSpaceCombo

职责：

- 判断起送价：原价小计 >= 门店起送价。
- 判断商品原价小计范围：原价小计必须落在成本测算页设置的最低/最高范围内。
- 不读取门店满减和门店订单优惠券。
- 扣除测算页设置的满减/券预留空间。实际扣减额使用 `min(settings.couponSpace, originalTotal)`，因此不会超过用户填写值。
- 使用扣除满减/券空间后的金额命中平台基础神券/爆红包。
- 扣除平台基础神券/爆红包后，再扣除测算页设置的神券/爆红包加码空间。
- 判断整单用户实付是否落在支付价区间。
- 计算佣金、外卖服务费、运费补贴。
- 使用用户实付和主食份数命中定价策略阶梯。
- 同时计算实付利润率和到手利润率：净实付 = 用户实付 - 佣金 - 外卖服务费 - 运费补贴。

### allocateCostSpaceItems

职责：

- 按含打包费原价占比分摊满减/券预留空间。
- 使用券后金额占比分摊平台基础神券/爆红包。
- 使用红包后金额占比分摊整单用户实付、平台费用和加码预留空间。
- 使用商品净分摊实付计算商品利润和到手利润率：商品净分摊实付 = 商品分摊用户实付 - 商品分摊平台费用。
- 使用商品分摊用户实付计算实付利润率。
- 剩余优惠空间取两种口径中更紧的值：`利润 - 商品净实付 * 到手目标率`、`利润 - 商品用户实付 * 实付目标率`。
- 得到商品用户实付、商品净实付、成本、利润、实付利润率、到手利润率、策略档位和剩余优惠空间。

### buildCostPriceSuggestion

职责：

- 找到商品所有组合明细中目标利润率缺口最大的组合。
- 使用缺口金额、组合内商品数量和当前净实付效率估算单品需要加价的金额。
- 建议价按 0.1 元向上取整。
- 建议价只作为人工确认后的平台价调整依据，不自动改价。

## 分摊方案说明

分摊基准选择“含打包费原价经过满减/券预留空间、平台基础神券/爆红包扣减后的商品金额”，而不是成本占比：

- 优点：更贴近用户实际支付结构，价格高的商品承担更多优惠和费用。
- 优点：能诊断销售价是否合理，这是本功能的目标。
- 缺点：高毛利商品会承担更多平台红包分摊，但这是价格结构诊断所需的保守口径。

成本占比分摊暂不采用：

- 成本占比适合做成本归因，不适合判断销售价承载活动空间。
- 低成本高售价商品如果按成本占比分摊，会低估它对组合优惠空间的承载能力。

## 防死循环策略

- 枚举深度固定为商品数量。
- 每层 SKU 数量范围固定为 `0..min(maxQtyPerSku, maxItems - totalQty)`。
- `maxChecks` 超限后停止。
- 总价范围通过后缀最大价格提前剪枝。
- 每个组合只计算有限平台列表。

## 页面交互

- 成本测算页顶部展示测算参数。
- 利润率目标显示和异常判断来自平台通用定价策略阶梯。
- 点击生成后刷新诊断结果。
- 点击商品名称展示该商品所有组合明细。
- 组合明细展示“满减/券空间”，不得展示或计算门店订单券。
- “满减/券空间”列应等于本次组合实际扣减的预留空间，正常不超过 `settings.couponSpace`。
- 图表使用商品组合明细数据绘制利润率曲线。
- 生成测算时按钮和结果表格必须显示 loading 状态，避免长时间枚举时用户没有反馈。

## 本地数据库策略

- 调整成本测算技术方案和页面交互不删除浏览器 IndexedDB。
- 只有出现无法兼容读取的结构升级时，才允许设计显式迁移方案；迁移方案优先做数据转换，不直接清库。
- 新字段必须通过默认值和 `normalizeState` 兼容旧数据。
