# 定价策略模型需求与技术设计

## 目标

定价策略用于统一活动设计、定价评估、测算结果和组合预警的利润率判断口径。模型以用户实付作为分档依据，按单人、双人、多人分别维护利润率阶梯，实现低客单价优先不亏、高客单价逐步让利，从而提升加购和套餐的价格吸引力。

## 核心口径

- 分档依据：最终用户实付。
- 场景依据：组合主食份数，1 份为单人，2 份为双人，3 份及以上为多人；0 份按单人兜底。
- 利润金额：商家到手价 - 商品成本。
- 商家到手价：用户实付 - 平台佣金 - 外卖服务费 - 配送补贴。
- 实付利润率：利润金额 / 用户实付。
- 到手利润率：利润金额 / 商家到手价。

## 阶梯字段

每个单人、双人、多人场景各自维护多行阶梯：

- 实付最低。
- 实付最高；最后一档可设置为 9999 表示不限。
- 实付利润率下限。
- 实付利润率目标。
- 到手利润率下限。
- 到手利润率目标。
- 是否启用。

下限用于预警和“低于下限”标记；目标用于定价建议、成本空间和活动设计回归。

## 默认策略

- 单人 20 元以内、双人 40 元以内、多人 60 元以内：目标为不亏，适配引流和低客单场景。
- 中间客单价：保持较高利润率，保护主食利润。
- 高客单价：目标利润率逐步降低，让用户加购或选择更高客单价组合时更划算。

## 计算规则

1. 根据组合主食份数得到单人、双人或多人场景。
2. 根据最终用户实付匹配该场景下的阶梯。
3. 同时计算实付利润率和到手利润率。
4. 任一口径低于对应下限，组合标记为“低于下限”。
5. 任一口径低于对应目标，组合标记为“低于目标”。
6. 若利润金额小于 0，始终标记为亏损。
7. 允许低于下限的组合进入结果，但必须在明细中标注，方便定位问题组合。

## 页面影响

- 平台规则页新增“平台通用定价策略阶梯”，通过单人、双人、多人 Tab 维护。
- 活动设计不再使用固定目标利润率，满减和订单券按命中组合的策略目标回归；用券后按“用券下浮百分点”放宽目标。
- 定价评估不再使用商品类型独立保护；套餐、饭团等均按商品维护中的主食份数进入单人、双人、多人策略。
- 组合预警使用策略下限，分别判断实付利润率和到手利润率。

## 数据兼容

新增 `pricingStrategy` 字段后，旧浏览器数据读取时通过 `normalizeState` 自动补默认策略，不删除本地数据库。后续迁移 PostgreSQL 时，对应表为 `platform_pricing_strategy_tiers`。
