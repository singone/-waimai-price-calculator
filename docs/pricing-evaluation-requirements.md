# 定价评估需求文档

## 目标

定价评估用于按商品类型生成多套建议平台价，并用成本占比判断当前售价是否合理。页面展示支付价、佣金配送费、商家到手、到手率和成本占比，不再使用利润率口径或利润基数。凑单商品会参考主食定价比例，但不直接摊派配送减免、配送服务费、基础活动和其他固定活动支出。

页面不生成活动方案，不自动批量改价；活动路线仍由“活动设计”负责。

## 定价方案

页面支持一次生成多套定价方案：

- 引流方案：允许更高成本占比，减少凑单商品对主食比例和阶梯优惠的承接，售价更有吸引力，适合拉新、冲单和测试转化。
- 均衡方案：沿用页面基准成本占比，兼顾利润和价格接受度。
- 利润方案：要求更低成本占比，增加凑单商品对主食比例和阶梯优惠的承接，减少套餐让利，适合毛利修复。

用户可以多选要生成的方案。生成后页面先展示每套方案实际生效的定价规则明细，再展示商品建议价；结果区支持按方案筛选后应用对应建议价。

## 统一公式

主食、套餐和其他商品按平台费用规则计算真实支付和到手：

```text
支付价 = 含费价 - 基础神券/爆红包 - 配送费减免 - 其他固定活动支出
佣金 = max(支付价 × 佣金率, 保底佣金)
配送服务费 = 按支付价、配送距离和下单时段计算
佣金配送费 = 佣金 + 配送服务费
商家到手 = 支付价 - 佣金配送费
到手率 = 商家到手 / 支付价
成本占比 = 成本价 / 支付价
```

诊断以成本占比为基础，同时检查是否低于策略建议价：

```text
成本占比 <= 目标成本占比：达标
成本占比 > 目标成本占比：需要提高售价或优化成本
当前售价低于策略建议价：需要提高售价
```

如果当前商品已经命中基础神券/爆红包，建议价搜索会继续承接当前已命中的基础活动金额和对应门槛，避免通过降到活动门槛以下绕开已配置支出。

## 商品定价策略

### 主食

主食承担商品成本、基础活动、佣金、配送服务费、配送费减免和其他固定活动支出。建议价从最低候选含费价开始按 0.1 元递增，取第一个满足成本占比不高于目标成本占比的价格。

### 凑单商品

凑单商品包含小吃饮料、加料、单点不送且主食份数为 0 的商品；未归类但主食份数为 0 的非主食商品也按凑单商品处理。

凑单商品不承担配送减免、配送服务费、基础活动和其他固定活动支出，避免低成本小吃被定得过高。但凑单商品会参与“主食 + 小吃”的订单总价和活动梯度，因此需要参考主食定价比例，防止小吃过低价成为大额券或下一档优惠的套利入口：

```text
凑单支付价 = 凑单含费价
凑单商家到手 = 凑单支付价
凑单成本占比 = 凑单成本 / 凑单支付价
主食定价比例 = Σ(同方案主食建议含费价) / Σ(主食成本)
凑单成本占比底价 = 凑单成本 / 凑单目标成本占比
主食参考价 = 凑单成本 × 主食定价比例
凑单比例底价 = 凑单成本占比底价 + max(主食参考价 - 凑单成本占比底价, 0) × 承接主食比例
新增优惠 = max(单个活动项在 主食单点 到 主食 + 凑单候选价 之间增加的优惠)
阶梯风险底价 = 凑单成本占比底价 + 新增优惠 × 优惠承接比例
凑单建议价 = max(凑单成本占比底价, 凑单比例底价, 品类最低售价, 阶梯风险底价) 后按 0.1 元取价
```

承接主食比例默认 70%。设置为 0 时，凑单商品不向主食定价比例靠拢；设置为 100% 时，凑单商品完全按主食定价比例承接。

品类最低售价默认 1.9 元，用于解决泡菜、茶叶蛋等低成本小吃按成本倍率计算后售价过低的问题。

优惠承接比例默认 80%。新增优惠来自门店当前平台的满减、优惠券、基础神券/爆红包和红包加价阶梯。系统会用所有上架主食作为参考，计算“主食单点”和“主食 + 当前凑单小吃候选价”之间，单个活动项最多增加多少优惠，再按承接比例抬高凑单商品底价。

这里不把所有活动项的差额相加，也不把起送资格本身当成小吃要承担的优惠。这样小吃承担的是“跨下一档导致的主要新增优惠”，不是整单活动成本。

示例：

```text
成本占比底价 = 0.3 / 50% = 0.6
新增优惠 = 2
优惠承接比例 = 80%
阶梯风险底价 = 0.6 + 2 × 80% = 2.2
品类最低售价 = 1.9
最终建议价 = max(0.6, 主食比例价, 1.9, 2.2) = 2.2
```

主食定价比例使用该平台所有上架主食，商品名称筛选和含费价筛选不会改变凑单参考比例。

### 套餐

套餐需要在商品维护页配置组成商品。定价评估先汇总组成商品建议价，再扣套餐折扣，并与套餐成本占比底价取较高值：

```text
套餐基准价 = Σ(组成商品建议含费价 × 数量)
套餐折扣价 = 套餐基准价 × (1 - 套餐折扣率)
套餐成本占比底价 = 满足 套餐成本 / 支付价 <= 套餐目标成本占比 的最低 0.1 元含费价
套餐建议价 = max(套餐折扣价, 套餐成本占比底价) 后按 0.1 元取价
```

未配置组成的套餐仍进入结果，但标记为配置问题，并按套餐自身成本反推底价。

## 页面输入

- 平台筛选：全部、美团、饿了么。
- 生成方案：引流、均衡、利润，可多选。
- 商品名称筛选：按商品名模糊匹配。
- 含费价最低/最高：按平台售价加打包费筛选。
- 基础活动口径：最低、平均、最高，对应平台规则中的神券/爆红包档位。
- 其他固定活动支出：除基础神券/爆红包外，每单额外固定支出。
- 主食目标成本占比。
- 凑单目标成本占比。
- 凑单承接主食比例。
- 凑单品类最低售价。
- 凑单优惠承接比例。
- 套餐目标成本占比。
- 套餐折扣率。

## 关联配置

- 平台佣金率、保底佣金、配送服务费、配送费减免来自平台规则页。
- 美团基础神券、饿了么基础爆红包来自平台规则页。
- 满减、优惠券、红包加价来自当前门店活动配置，用于计算凑单小吃的新增优惠风险。
- 商品成本、平台价、打包费、分类、主食份数来自商品维护页。
- 套餐组成来自商品维护页。

## 应用建议价

用户可以单行应用建议价：

- 应用的是当前结果行所属定价方案的建议价。
- 建议价只写入当前商品对应平台价。
- 不修改另一个平台价格。
- 不修改统一销售价。
- 不修改打包费。
- 应用后需要重新生成定价规则查看新结果。

## 非目标

1. 不自动批量改价。
2. 不生成活动方案。
3. 不枚举完整订单组合。
4. 不替代活动设计页的路线校验。
