# 网站功能调整任务单（按经营目的筛选）

修订日期：2026-10-14。以 [网站目的与差异筛选计划](website-adjustment-plan-2026-10-14.md) 为准，替代上一版25项任务。此前F01–F11等编号停止作为执行依据，避免继续推进过度改造。执行进度见下文。

目标：正确测算最大可用优惠下的最低实付及对应商家到手/利润，支持定价、活动和风险判断。后台存在差异不等于网站需要改造。

| ID | 优先级 | 类型 | 任务 | 完成标准 |

| N02 | P0 | 配置 | 修正5条加量SKU绑定，核实对应成本及套餐组成 | 售价与成本属于同一规格；排除错绑后的导入再比较 |
| N03 | P0 | 配置/默认值 | 修40减12默认门槛、减3券0.01门槛 | 门槛边界正确；已保存正确配置不被覆盖 |

| N05 | P1 | 配置 | 重新比较商品售价、上下架及需要参与测算的档案 | 复用现有核对入口；旧16项价格/4项状态仅作候选，不直接批量照搬 |

| N07 | P0 | 验证 | 检查最低价选券及对应分摊，验证门槛和凑单跨档 | 不拼接不可同时使用的优惠；最低实付和到手来自同一方案；风险可解释 |

顺序：N01 → N02/N03/N04 → N05/N06 → N07 → N08。后台各项可独立核对，不要求全平台采集完成后才处理已确认配置。

## 先验证，有缺口才开发

| ID | 触发条件 | 最小改造 | 验证要求 |
| --- | --- | --- | --- |
| C01 | 实际小额券存在非零最大加码，而现有功能清零或不计算 | 复用固定加码字段，打通大小券编辑、保存、归一化、导入导出及求值 | 最大金额往返不丢失，结果正确；不引入人群和时段规则 |
| C02 | 现有商品关键词无法准确表达实际折扣范围，并已造成误算 | 增加明确商品选择或局部范围控制 | 目标商品命中，套餐等非目标商品不误折扣 |
| C03 | N07证实现有选券或分摊算法无法给出最低价与对应到手 | 修相关选券、分摊逻辑及受影响的缓存 | 用发现问题的真实组合回归；不改变活动设计和定价评估各自职责 |
| C04 | N06证实真实费用结构不能用现有配置表达，且影响到手判断 | 扩展对应费用计算，不重建整个平台计费系统 | 用已取得的规则和金额样本验证；保持门店平台隔离 |

只有触发条件成立才进入开发排期，不能提前当作确定缺陷。

## 明确不做

- D05人群、时段、预订资格引擎；D06平台出资触发引擎；D07渠道券阶梯异常功能。
- 为后台名称、分类、活动数量一致而新增页面、字段或重复券。
- 通用活动身份系统、字段级证据平台、库存实时模拟与全量后台镜像。
- 预测平均成交价、人群概率，或为本轮核对重构全站。
