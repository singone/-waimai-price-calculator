# 定价评估技术方案

## 设计原则

- 定价评估独立于成本测算和活动设计运行。
- 只考虑商品平台价、打包费、成本、平台基础神券/爆红包、加码空间和平台费用。
- 不读取门店满减、订单券、商品折扣和门店活动加码。
- 不做全商品组合枚举，改为按商品生成有限压力场景，避免指数级组合导致页面长时间无结果。

## 核心流程

1. 根据平台筛选生成待测平台。
2. 按商品名、平台上下架过滤待测商品。
3. `pricingProductType` 自动识别商品类型。
4. `buildPricingProductScenarios` 为每个商品生成单品、起送、费用阶梯和平台红包门槛压力场景。
5. `evaluatePricingProductScenario` 计算场景整单价格、平台红包、加码、平台费用和单品分摊利润率。
6. 按 `platform + productId` 聚合商品诊断。
7. 使用缺口最大场景估算建议平台价。

复杂度从全组合枚举的指数级，收敛为：

```text
平台数 * 商品数 * (单品份数 + 费用阶梯数 + 平台红包门槛数)
```

## 目标利润率

目标利润率由单品目标和订单目标共同决定。

`pricingProductType` 自动识别商品类型：

- `addOn`：单点不送，或名称包含凑单、加购、小料、配菜、蘸料、调料、小份等关键词。
- `setMeal`：名称包含套餐、套饭、组合、单人餐、双人餐、多人餐等关键词，或包含 `+` / `＋` 这类多品组合符号；该规则优先于饭团规则。
- `riceBall`：名称包含饭团且未命中套餐规则。
- `normal`：其他商品。

`pricingProductTargetRate` 返回商品类型目标：

- 普通：平台通用规则 `pricingEvaluation.fallbackTargetProfitRate`。
- 凑单：平台通用规则 `pricingEvaluation.addOnTargetProfitRate`。
- 饭团：平台通用规则 `pricingEvaluation.riceBallTargetProfitRate`。
- 套餐：平台通用规则 `pricingEvaluation.setMealTargetProfitRate`。

`pricingRequiredRate` 负责匹配订单目标利润率：

- `finalPay <= lowPayMax`：返回 0，表示只要求不亏损。
- `finalPay > lowPayMax` 且命中利润率阶梯：返回阶梯 `rateMin / 100`。
- 未命中利润率阶梯：返回平台通用规则 `pricingEvaluation.fallbackTargetProfitRate / 100`。

`pricingRequiredRateForProduct` 取商品类型目标和订单目标的较高值，作为最终目标利润率。

定价评估页面只维护筛选、支付价范围、低价不亏上限和神券/爆红包加码空间；四类商品目标利润率从平台通用规则继承。

## 压力场景

`buildPricingProductScenarios` 生成以下场景：

1. 可单点商品：生成 `1..maxQtyPerSku` 的单品场景。
2. 单点不送商品：生成“当前商品 + 最低可单点商品”的凑单分摊场景。
3. 起送压力：订单原价至少达到门店起送价、测算总价下限和页面原价下限。
4. 费用阶梯：生成 20 元和 25 元附近场景，用于覆盖外卖服务费价格段变化。
5. 平台红包门槛：按当前平台基础神券/爆红包每个启用门槛生成压力场景。

场景会去重，并继续受门店测算总价范围、页面原价范围和页面支付价范围约束。

## 场景计算

`evaluatePricingProductScenario` 执行：

1. 使用场景原价命中平台基础神券/爆红包。
2. 扣除基础神券/爆红包和页面加码空间。
3. 过滤最终用户实付范围。
4. 计算佣金、外卖服务费和运费补贴。
5. 按当前商品在场景原价中的占比分摊红包。
6. 按红包后占比分摊最终用户实付和平台费用。
7. 商品利润 = 商品净分摊实付 - 商品成本。
8. 商品剩余空间 = 商品利润 - 商品净分摊实付 * 最终目标利润率。
9. 商品亏损或低于目标时计入异常场景。

## 商品分摊

商品分摊使用价格贡献：

1. 按含打包费原价占比分摊平台基础神券/爆红包。
2. 按红包后金额占比分摊最终用户实付和平台费用。
3. 商品利润 = 商品净分摊实付 - 商品成本。
4. 商品剩余空间 = 商品利润 - 商品净分摊实付 * 最终目标利润率。
5. 商品亏损或低于目标时计入异常组合。

## 建议价估算

建议价使用 `buildPricingPriceSuggestion`：

- 若存在低于目标的场景，找到目标缺口最大的场景。
- 按场景内该商品数量分摊缺口，并使用净实付效率修正加价金额。
- 若真实缺口价相对当前平台价的增幅不超过 0.30 元，认为评估误差可接受，不输出建议价。
- 若真实缺口超过 0.30 元，按“平台售价 + 当前平台打包费”的含打包费价向上取最近的 `x.9` 尾价，再反推需要写入的平台售价。
- 若不存在低于目标的场景，则检查所有场景的剩余空间。
- 只有所有场景都有正向剩余空间时，才按最紧压力场景反推最大安全降价空间。
- 若安全降价空间超过 0.30 元，则按含打包费价向下调整到不打穿目标的最近 `x.9` 尾价，再反推平台售价；否则不输出建议价。
- 应用建议价只修改平台售价覆盖值，不自动修改统一打包费或平台打包费。

## 页面交互

- 左侧导航提供“定价评估”入口。
- 生成时展示 loading 和进度指标。
- 表格展示商品级诊断和建议平台价。
- 单行“应用建议价”只写入当前平台价覆盖字段。
