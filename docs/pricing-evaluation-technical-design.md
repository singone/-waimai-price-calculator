# 定价评估技术方案

## 设计原则

- 定价评估只负责生成商品建议价和当前售价诊断。
- 定价评估支持一次生成多套内置定价方案。
- 商品按主食、凑单商品、套餐、其他四类策略处理；小吃饮料、加料、单点不送、未归类且主食份数为 0 的非主食商品归入凑单商品。
- 平台费用和基础神券/爆红包复用平台规则页配置。
- 商品成本、分类、主食份数、套餐组成复用商品维护页配置。
- 建议价统一按含打包费价以 0.1 元精度取价，再反推需要写入的平台价。

## 数据模型

`Product` 新增可选字段：

```text
bundleItems: { productId, qty }[]
```

只有套餐商品使用该字段。旧商品没有该字段时自动归一化为空数组。

`PricingEvaluationSettings` 包含：

- 商品筛选和含费价范围。
- 需要生成的定价方案 key 集合。
- 主食目标成本占比。
- 凑单目标成本占比。
- 凑单承接主食比例。
- 凑单品类最低售价。
- 凑单优惠承接比例。
- 套餐目标成本占比、套餐折扣率。
- 基础活动金额口径。
- 其他固定活动支出。

`PricingProductRow` 每行绑定一个定价方案：

```text
planKey, planName, planDescription
```

`PricingEvaluationResult` 同时返回 `planRules` 和 `productRows`。`planRules` 是本次生成的定价规则快照，每行包含：

```text
planKey, planName, planDescription,
stapleTargetCostShare, addOnTargetCostShare, addOnStapleRatioShare,
addOnMinimumOriginalPrice, addOnPromotionRiskShare,
setMealTargetCostShare, setMealDiscountRate,
fixedActivityCost, baseRedAmountMode
```

同一平台同一商品会按启用方案生成多行结果，用户应用建议价时应用当前行所属方案的价格。

## 定价方案预设

定价方案定义在 `src/domain/pricing/pricingPlans.ts`：

- 引流方案：主食、套餐和凑单商品目标成本占比提高 6 个百分点，凑单承接主食比例和优惠承接比例降低 10 个百分点，套餐折扣率提高 5 个百分点。
- 均衡方案：使用页面基准参数。
- 利润方案：主食、套餐和凑单商品目标成本占比降低 5 个百分点，凑单承接主食比例和优惠承接比例提高 10 个百分点，套餐折扣率降低 4 个百分点。

## 核心流程

1. 根据平台筛选生成待测平台。
2. 读取当前门店实际使用的平台费用规则。
3. 按商品名、平台上下架和含费价范围过滤商品。
4. 按启用方案展开每个平台的计算任务。
5. 每个方案内先计算主食和其他商品建议价，并缓存每个商品的建议含费价。
6. 再基于同方案主食建议价计算主食定价比例，随后计算凑单商品建议价。
7. 最后计算套餐商品，套餐组成优先使用同方案内已缓存的组成商品建议含费价。
8. 按商品当前售价计算支付价、佣金配送费、商家到手、到手率和成本占比。
9. 按成本占比缺口、策略建议价缺口和配置缺失生成诊断等级。
10. 输出“方案 + 平台 + 商品”级结果。

## 费用计算

定价评估按候选含费价动态计算费用：

```text
基础活动 = 命中平台基础神券/爆红包档位后的最低、平均或最高金额
配送费减免 = 按配送距离命中平台规则
支付价 = 含费价 - 基础活动 - 配送费减免 - 其他固定活动支出
佣金 = max(支付价 × 佣金率, 保底佣金)
配送服务费 = 配送距离费 + 20/25 元价格段服务费 + 时段费
佣金配送费 = 佣金 + 配送服务费
商家到手 = 支付价 - 佣金配送费
到手率 = 商家到手 / 支付价
成本占比 = 成本口径 / 支付价
```

成本口径：

- 主食、凑单商品、其他商品使用商品自身成本。
- 已配置组成的套餐使用组成商品成本合计。
- 未配置组成的套餐使用套餐自身成本，并标记配置问题。
- 凑单商品不扣基础活动、配送服务费、配送费减免和其他固定活动支出，避免重复承接已经放到主食或套餐上的整单固定支出。

## 建议价计算

主食和其他商品：

```text
从最低候选含费价开始按 0.1 元递增，取第一个满足 成本占比 <= 目标成本占比 的价格。
```

若当前商品已经命中基础神券/爆红包，建议价搜索会把当前基础活动金额作为最低承接金额，并把当前命中的活动门槛作为候选价下限，避免建议价通过降档绕开已配置活动。

凑单商品：

```text
凑单支付价 = 凑单含费价
凑单商家到手 = 凑单支付价
凑单成本占比 = 商品成本 / 凑单支付价
主食定价比例 = Σ(同方案主食建议含费价) / Σ(主食成本)
凑单成本占比底价 = 商品成本 / 凑单目标成本占比
主食参考价 = 商品成本 × 主食定价比例
凑单比例底价 = 凑单成本占比底价 + max(主食参考价 - 凑单成本占比底价, 0) × 凑单承接主食比例
凑单候选价 = max(凑单成本占比底价, 凑单比例底价, 品类最低售价)
新增优惠 = max(单个活动项在 主食单点 到 主食 + 凑单候选价 之间增加的优惠)
阶梯风险底价 = 凑单成本占比底价 + 新增优惠 × 优惠承接比例
最低候选价 = max(凑单成本占比底价, 凑单比例底价, 品类最低售价, 阶梯风险底价)
```

示例：

```text
成本占比底价 = 0.3 / 50% = 0.6
新增优惠 = 2
优惠承接比例 = 80%
阶梯风险底价 = 0.6 + 2 × 80% = 2.2
品类最低售价 = 1.9
最终建议价 = max(0.6, 主食比例价, 1.9, 2.2) = 2.2
```

凑单商品不使用整单费用计算器，不扣基础活动、配送服务费、配送费减免和其他固定活动支出。主食定价比例使用该平台所有上架主食，优先取同方案已计算出的主食建议含费价，没有进入当前筛选结果的主食使用当前含费价兜底。主食定价比例只作为凑单商品参与订单活动梯度时的价格底线，避免低价小吃在大额券或下一档优惠中造成组合亏损。

新增优惠来自当前门店当前平台配置的满减、优惠券、基础神券/爆红包和红包加价。计算时用所有上架主食逐个模拟“主食单点”和“主食 + 凑单候选价”，分别计算每个活动项自身的优惠增量，取最大单项增量作为该小吃的阶梯风险。

新增优惠不叠加多个活动项差额，也不因主食单点未达到起送价而把整单活动全量压到小吃上。

套餐：

```text
套餐基准价 = Σ(组成商品建议含费价 × 数量)
套餐折扣价 = 套餐基准价 × (1 - 套餐折扣率)
套餐成本占比底价 = 第一个满足 套餐成本 / 支付价 <= 套餐目标成本占比 的 0.1 元含费价
最低候选价 = max(套餐折扣价, 套餐成本占比底价)
```

候选价最终反推平台价：

```text
建议平台价 = 建议含费价 - 当前平台打包费
```

当前价与建议价差不超过 0.30 元时，视为可接受误差，不输出调价动作。

## 诊断等级

- 高：当前成本占比高于目标成本占比，或当前售价低于策略建议价。
- 中：保留给后续非成本类风险；当前价高于策略价只作为正常结果中的提示，不计入异常。
- 配置：商品缺成本、支付价无法计算、缺少可参考主食定价比例、套餐缺组成或组成失效。
- 正常：当前定价符合策略。

## 页面交互

- 定价评估页维护本次测算参数，不直接修改平台规则。
- 定价评估页支持多选生成方案，点击生成后产出本次定价规则快照和商品定价结果。
- 定价规则明细在结果表上方展示；未生成前展示当前选择的预览规则，生成后展示本次计算实际使用的规则。
- 商品诊断弹窗展示所属方案的完整规则，并展示凑单商品的成本占比底价、主食比例价、品类最低价、新增优惠、阶梯风险底价和最终取价依据。
- 定价结果支持按方案筛选。
- 商品维护页提供套餐组成编辑入口。
- 单行应用建议价只写入当前方案当前商品的对应平台价覆盖字段。
- 应用建议价后清空当前结果，要求用户重新生成评估。
