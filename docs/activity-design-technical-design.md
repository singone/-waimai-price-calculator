# 活动设计技术方案

## 设计原则

- 活动设计独立于成本测算运行，不在成本测算结果里夹带生成。
- 活动设计不复用门店已有满减、订单券、商品折扣和门店加码配置。
- 组合枚举使用 `enumerateStoreCombosAsync`，统一过滤门店测算总价范围和主食份数范围，并分块让出浏览器主线程，避免页面卡死。
- 候选门槛使用有限抽样，减额使用反推搜索加局部候选复核，避免密集遍历。
- 利润率目标来自平台通用定价策略阶梯，不再使用页面固定目标利润率。

## 核心流程

1. 根据平台筛选生成待测平台列表。
2. 使用 `enumerateStoreCombosAsync` 枚举当前门店组合。
3. `buildCouponDesignBaseRow` 生成活动设计基础组合：
   - 平台上下架过滤。
   - 门店测算总价范围过滤。
   - 门店主食份数范围过滤。
   - 原价小计范围过滤。
   - 起送价过滤。
   - 商品名称筛选过滤。
4. `buildCouponDesignRowsAsync` 按平台分别生成候选活动，并在门槛处理过程中分块让出浏览器主线程。
5. 输出活动设计建议表。

## 候选门槛

门槛口径支持两种：

- `original`：使用含打包费原价小计。
- `pay`：使用基准支付价。基准支付价 = 原价小计 - 平台基础神券/爆红包 - 本页神券/爆红包加码空间。

候选门槛按 `couponDesignThresholdStep` 向下归并，并最多保留 30 个门槛；超过 30 个时做均匀抽样。

## 候选减额

候选减额不再从 0 到最大值密集遍历。系统先按目标利润率反推减额，再只复核目标值附近的少量候选：

1. 使用最多 250 个代表组合快速定位建议满减。
2. 满减场景目标来自每个组合命中的定价策略阶梯，用于保证无券用户接近目标利润率。
3. 用券场景目标为“命中策略目标 - couponProfitDrop”，用于控制单张订单券后的利润率下浮。
4. 金额定位后，仅复核 `目标减额 - 步长`、`目标减额`、`目标减额 + 步长` 三个局部候选。
5. 局部候选必须再用当前门槛下的全量命中组合做最终校验。

单项限制：

- 满减金额不超过 `couponDesignMaxFullAmount`。
- 券金额不超过 `couponDesignMaxCouponAmount`。
- 任意减额必须小于门槛。

## 活动类型

`buildCouponDesignRowsAsync` 按活动类型生成候选方案：

- `full`：只反推满减，订单券 = 0。
- `coupon`：满减 = 0，只反推一张订单券；无券场景不扣券。
- `stacked`：先反推满减作为无券用户基线，再在该满减基础上反推一张订单券。
- `auto`：同时生成以上三类候选。

## 方案模拟

`simulateCouponDesignRow` 对每个候选组合执行：

1. 扣建议满减。
2. 用券模拟扣建议订单券；无券模拟的订单券金额固定为 0。
3. 使用扣后金额重新命中平台基础神券/爆红包。
4. 扣平台基础神券/爆红包。
5. 扣本页神券/爆红包加码空间。
6. 判断最终用户实付是否落入支付价范围。
7. 计算佣金、外卖服务费和运费补贴。
8. 计算整单到手价、利润、实付利润率和到手利润率。
9. 按最终用户实付和主食份数命中定价策略阶梯。

候选活动的硬性过滤规则：

- 任一命中组合的利润金额小于 0 时，直接丢弃该候选活动。
- 无券平均实付利润率或到手利润率低于对应策略目标时，直接丢弃该候选活动。
- 用券平均实付利润率或到手利润率低于“对应策略目标 - 用券下浮百分点”时，直接丢弃该候选活动。
- 该过滤发生在平均利润率排序之前，因此不会出现“平均利润率接近目标但部分组合亏损”的建议。

## 排序

每个候选门槛保留一个最优方案：

1. 无券平均利润率与策略目标的距离越小越优。
2. 用券平均利润率与下浮后策略目标的距离越小越优。
3. 无券和用券利润率波动越小越优。
4. 距离相同，命中组合数越多越优。
5. 距离和命中数相同，总优惠越小越优。

最终返回前 30 个候选方案。

## 页面交互

- 左侧导航提供独立“活动设计”入口。
- 点击“生成活动设计”只刷新活动设计结果，不触发成本测算。
- 生成过程中展示 loading，并实时更新检查组合数、有效组合数和候选方案数。
- 结果只展示，不自动保存为门店活动。
