# 活动设计需求文档

## 目标

活动设计用于在当前门店商品价格、打包费、成本、平台基础神券/爆红包和预设神券/爆红包加码空间下，反推建议的门店满减、订单券或满减加订单券叠加方案。

门店满减是所有用户都享有的活动，目标是让无券用户的平均利润率靠近目标利润率。订单券是发给用户的单张券，同一订单最多使用一张，允许用券用户的利润率比目标利润率低几个百分点，但整体利润率仍需要平稳且不能亏损。

活动设计是独立功能，不随成本测算一起运行，也不读取当前门店已经配置的满减和订单券。

## 输入参数

- 平台筛选：全部、美团、饿了么。
- 商品名称筛选：按商品名模糊匹配，空值表示全部商品。
- 原价小计最低/最高：按 `(平台售价 + 当前平台打包费) * 数量` 筛选组合。
- 支付价最低/最高：筛选活动设计后的最终用户实付。
- 活动类型：自动推荐、只设计满减、只设计订单券、满减加券叠加。
- 门槛口径：按原价小计或按基准支付价。
- 神券/爆红包加码空间：作为本次设计的前置加码配置。
- 目标利润率。
- 用券下浮百分点：用券用户允许低于目标利润率的百分点，例如目标 25%、下浮 3，则用券目标为 22%。
- 门槛步长。
- 减额步长。
- 满减最大减额。
- 券最大减额。

## 组合范围

活动设计只使用真实可下单组合：

1. 商品必须在当前平台上架。
2. 组合必须满足门店起送价。
3. 组合必须满足门店测算总价范围。
4. 组合必须满足活动设计页原价小计范围。
5. 若填写商品名称筛选，只纳入包含命中商品的组合。
6. 设计后的最终用户实付必须满足活动设计页支付价范围。
7. 设计后的所有命中组合都不能亏损；任一组合利润小于 0 时，候选活动无效。

## 计算顺序

对每个平台分别计算，避免美团神券和饿了么爆红包阶梯混算：

1. 计算原价小计。
2. 判断候选活动门槛。
3. 扣除建议门店满减。
4. 若用户使用订单券，扣除建议订单券；无券用户不扣订单券。
5. 使用扣除满减和券后的金额命中平台基础神券/爆红包。
6. 扣除平台基础神券/爆红包。
7. 扣除活动设计页设置的神券/爆红包加码空间。
8. 得到用户实付。
9. 扣除佣金、外卖服务费和运费补贴，得到整单到手价。
10. 计算整单利润率。
11. 若任一命中组合利润小于 0，丢弃该候选活动。
12. 按无券利润率接近目标、用券利润率接近下浮目标、利润率波动更小的综合分排序输出建议。

## 叠加规则

- 只设计满减：仅输出建议满减，订单券为 0，按无券目标利润率评估。
- 只设计订单券：仅输出建议订单券，满减为 0；无券场景不扣券，用券场景扣一张券。
- 满减加券叠加：同一个门槛下同时输出满减和订单券；满减作为全量用户基线，订单券只影响用券用户。
- 自动推荐：同时比较只满减、只订单券和满减加券叠加方案。
- 所有类型都必须满足命中组合不亏损。

## 输出字段

- 平台。
- 建议满减。
- 建议订单券。
- 活动类型。
- 门槛口径。
- 总优惠。
- 命中组合数和可命中组合数。
- 覆盖率。
- 无券平均利润率。
- 无券利润率与目标利润率的偏差。
- 用券平均利润率。
- 用券目标利润率。
- 利润率波动。
- 用券最低利润率。
- 平均原价、平均用户实付、平均到手价。
- 平均基础神券/爆红包金额。
- 平均加码空间。
- 代表组合。

## 非目标

1. 不自动写入门店活动配置。
2. 不读取当前门店已经配置的满减、订单券、商品折扣或门店加码活动。
3. 不修改商品价格。
