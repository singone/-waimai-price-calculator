# 平台后台活动配置完善（2026-10-12）

本次完善配置和计算能力，未批量替换两店真实活动金额。后台尚未完整取得的活动，不根据名称、促销页或旧示例推断分摊和互斥条件。

三平台活动页共用“后台活动配置口径”：美团区分满减、订单券、神券加码和折扣；淘宝区分满减、订单券、爆红包加码和折扣，减配成本仍在平台费用维护；京东普通券和平台补贴券分开，券面额、商家承担、平台承担、加码分别核对。

订单券新增可编辑的人群、发放渠道、后台备注及与其他订单券是否同享。人群和渠道沿用既有领域字段，仅记录领取资格，不自动判断实际顾客身份；有效期可在备注记录，尚不自动过滤。下单返券需已领取，不能把本次返券计成本次即时折扣。

订单券同享直接参与所有复用 bestCouponOption 的组合、定价和京东分析。false表示该券必须单独使用；true表示可与其他允许同享的订单券组合，仍受门店最多券张数限制；留空保持旧配置行为，并显示需核对。计算比较单独大券和可叠加券组合，选合法优惠最大的组合，不能简单把券额排序后相加。该设置不代表订单券与满减、商品折扣或红包的跨活动同享规则已经核实。

保存及后台导入使用同一活动校验：非负金额、满减不超过门槛、有效折扣及整数件数、京东券面额等于商家和平台承担之和。商家加码单列；当前小额券模型不支持加码，非零加码阻止保存。新增京东券不预填29减20等未经后台确认金额，新增商品折扣为停用10折，须填实际活动后启用。既有数值保留。

JSON和活动模板导入保留渠道、人群、同享、备注。Excel/CSV字段为“发放渠道、适用人群、可叠加其他订单券、后台核对备注”；同享列填写是/否，空白沿用旧模型。后台特殊规则仍通过同步页明确标记并阻止同步。

仍待完整核查：三平台逐项活动有效期、适用SKU/规格、券领取资格、优惠门槛计费基数及跨活动叠加顺序。美团/淘宝通用券模型中的金额是商家承担，不能填写混合分摊券总面额来模拟结算；京东混合分摊使用专门补贴券表。
